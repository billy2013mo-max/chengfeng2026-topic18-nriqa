## 2. Confirmed findings (each with its evidence)

1. **Every model family converges to the same score.** Single models: pe_core_large 48.9–49.8 (3 seeds), phoenix
   pillars (two 7–8B VLMs and a three-backbone physics model, different split, different loss, different author)
   48.72 / 48.91 / 48.99. Ensembles: 6 Tier-1 towers 50.44, 3 phoenix pillars 50.53, s1 (8 towers) 51.04.
   Evidence: `results/r55/gates/*.json`, scoring of `results/phoenix/pillar*_cv5_oof.npz` with the same decoder.
2. **The labels themselves are only this consistent.** 844 labelled images share a source video with another
   labelled frame. Using the sibling frame's *human label* as the prediction scores **46.96** (sd 0.32 over 20
   draws). The 6-tower ensemble, which never sees the sibling (group folds), scores **50.90** on the same images.
   Among pairs where both frames have the defect, the grade is the same in 59% (模糊), 62% (纹理损失), 61% (过锐)
   and 46% (过度生成) of cases. Frames can differ for real, so this is an upper bound on annotation noise, not a
   measurement of it — but it shows the models already agree with the labels better than two labelled frames
   of the same video agree with each other.
3. **Errors are adjacent-grade confusions**, not missed defects (confusion matrices of the 6-tower OOF; e.g. 纹理损失
   P1: 695 right, 151 → P2, 176 → P0, 16 missed). Oracle grades on detected cells would give +9.4; oracle presence
   only +3.5 (`results/next55/diag_oof.json`).
4. **Auxiliary-objective experiments all failed**, on one architecture:
   | experiment | seeds | Δ Doc2S | CI90 |
   |---|---|---|---|
   | ranking ladders λ=0.5 | 2 | −0.72 | [−1.13, −0.30] |
   | ranking ladders λ=0.25 | 1 | −0.90 | [−1.42, −0.39] |
   | pipeline-tag head | 1 | −1.20 | [−1.72, −0.70] |
   | FLUX 过度生成 ladder + teacher KD (other session) | 1 | −0.40 | [−0.86, +0.07] |
   The FLUX ladder was also unreliable as supervision: instruction strength did not order the outputs (140 of 326
   kept tuples had to be re-ordered by measured deviation; 45 of 371 were dropped).
5. **The one-seed screens are confounded.** The seed-2026 baseline was trained by the original Tier-1 trainer; all
   experiments by `code/r55/train_testbed.py`. Every flagged run lost 0.3–0.5 on S_clean, including the tag head,
   which adds no extra batch. A no-flag control (`r55_ctrl_s2026`) is running to separate the two. See §6.
6. **OOF numbers are optimistic by construction.** The saved checkpoint per fold is the best epoch on that fold's
   validation score (`train_testbed.py:361-363`, SWA accepted only if within 0.08 of it, `:378`). The other session
   measured ≈0.5 between best-epoch and last-epoch validation scores. A full-fit model cannot do this selection.
7. **Seed noise is as large as the effects being searched for.** Single seeds: sd 0.47. Two-seed means: sd 0.14.
   Paired bootstrap on 3,573 images: ±0.4. A 654-image draw: sd 0.66; 140 images: sd 1.64.
8. **Cross-family ensembling is the only measured gain today.** s1 + 3 phoenix pillars, equal weights:
   **51.39 vs 51.04, +0.36, CI90 [+0.07, +0.64], P(Δ≤0)=0.02**, 6 of 8 folds up; S_clean +0.27, S_p0 +0.14,
   S_pos −0.07. Family-balanced weights (50/50) give +0.02, so equal weights it is — chosen before looking at
   anything but OOF. Caveat: the phoenix split groups slightly differently; 11 of my 3,049 groups (100 images)
   straddle phoenix folds, a small optimistic leak on the phoenix side.

## 3. Hypotheses (not established)

- H1. The ≈+2 offset between past site scores and strict OOF comes from the practice set being easier, not from
  the models. Unverified; the s1 reference upload would give one data point (sd 1.64).
- H2. Fixed five views per image for all epochs (noted by the other session in `train_testbed.py:84`) causes
  memorisation; random crops may help. Being tested there (`rcrop`).
- H3. Grade noise is partly systematic (batch/annotator convention: the supplementary batch has 0 clean images
  and 2× the P2 rate for 模糊/过锐). If the final set follows the first batch's convention, thresholds fitted on
  the pooled data are slightly off. Cannot be tested without final-set labels; only robustness checks are possible.
- H4. Noise-robust training (soft targets from a nested teacher, small-loss sample selection) would help more
  than any new signal. Plausible given finding 2; untested; needs a leak-free protocol.

## 4. Limitations, separated

**Modelling / data**
- Label consistency caps the metric (findings 1–3). No experiment that only changes the encoder or adds a loss
  has moved a two-seed mean by more than noise.
- All 513 clean images are in the first batch; the clean decision is learned from one batch only.
- 过度生成 grading is the weakest cell (P1 F1 ≈ 0.27; sibling agreement 46%).

**Evaluation**
- Checkpoint selection on the validation fold (finding 6).
- One-seed screens cannot detect effects < ≈1.0; the gate needs two seeds, 8 folds, ≈1.5 GPU-hours × 16.
- Baseline and experiment trainers differ for seed 2026 (finding 5).

**Training / inference efficiency**
- 16 concurrent pe jobs need all 8 GPUs for ≈60 min; two sessions share the box.
- The accepted stack exists only as 8-fold models; the shippable full-fit model has not been trained.
- No measured end-to-end latency or parameter total for the stack that would actually be submitted.

## 7. Roadmap

Protocol for every training experiment: `pe_core_large`, seeds 2026 and 2027, 8 folds, `--select fixed` once the
other session has validated it, reference = same trainer and same seeds, gate = `code/r55/gate_r55.py`
(Δ ≥ 0.30, P(Δ≤0) ≤ 0.20, S_p0 and S_clean not down > 0.10). One retry at most. test150 is never consulted.

- **Phase A (today, running).** A1 control `r55_ctrl_s2026` (no flags) vs the seed-2026 baseline → if |Δ| > 0.5
  the earlier one-seed screens are re-read against the control. A2 stack gate s1 vs s1+phoenix (done, §2.8).
  Stop: none.
- **Phase B (next, GPUs 6–7).** B1 full-fit of the six Tier-1 towers of s1 (`launch_fullfit.py`), reload check
  per tower. B2 measure parameters and per-image latency of the s1 path on one GPU. Success: all reloads
  reproduce stored outputs; latency < 15 s. Stop: any reload mismatch.
- **Phase C (after A1, if GPUs allow).** C4 within-fold noise-robust variant, two seeds. Success = gate PASS.
  Stop after one variant and one retry.
- **Phase D (owner + other session).** Combine full-fit s1 and full-fit phoenix under one decoder fitted on OOF;
  measure parameters and latency of the combination; decide on the cost trade-off; use an early evaluation.

Budget: Phase A ≈ 9 GPU-h, B ≈ 4 GPU-h, C ≈ 24 GPU-h. Disk: keep ≥ 80 GB free.
