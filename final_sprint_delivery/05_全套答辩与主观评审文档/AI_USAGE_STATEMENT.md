## 二、 四个典型人机协同攻坚实例（真实研发闭环复盘）

### 实例 1：证伪“盲目堆叠大参数 VLM”误区，定位分布偏移根因
- **问题出现**：中期尝试训练并接入重型双底座（`InternViT-6B` + 高分辨率 `Qwen3-VL-8B`）且在离线校准时取消补充集降权（`w_supp=1.0`），线上提交分数不升反降。
- **人类关键判断**：第一时间根据打榜反馈指出 **“事实证明我们并不需要堆砌重型 VLM，最优路线仍是共享视觉骨干专家 + 精准边界校准”**，要求回溯此前 `54.3` 版本究竟改变了哪两格及其数学本质。
- **AI 根因定位**：编写逐格差分与概率轨迹审计脚本，定位出重型版本暴跌的两大机制性原因：
  1. 补充集 `supp_1671` 含 `0%` 全无问题（Clean）样本且 `P2` 比例偏高，移除 `w_supp=0.15` 导致 `DirDiag` 截距被拉偏，进而使期望效用参数从 `(2.75, 1.0)` 跳变为 `(2.25, 0.85)`，将 6 个真实的 `过度生成` `P0/P1` 样本错误降级为 `P2`；
  2. 移除 1:1 像素级显微镜专家（`v16`、`ntg_convnext`、`pe_bkseg1`）损失了高频局部伪影灵敏度。

### 实例 2：从单类洞察到三类痛点与 1:1 切片尖峰持续突破——`deconf_v2 → deconf_v4_tile`
- **人类关键启发**：在确认 `过度生成` 的收益来自“跨尺度（1:1 切片 vs 全局缩放）与跨缺陷去混淆校准”后，人类研究者连续提出两个核心科学问题：① **“针对同样存在局部/全局不一致与边界混淆的 `过锐` 和 `虚化突兀`，能否复用同一范式做针对性提分且无过拟合风险？”**；② 在 `deconf_v2` 线上取得 **`54.44`（`Clean = 20.00/20` 满分）** 后，进一步追问 **“Decoder 侧是否还有零过拟合的高价值信号未被利用？”**
- **AI 建模与防过拟合实现**：
  1. 在 [`code/r55/upgrade_os_og_bokeh_deconf.py`](file:///wanqing-develop/luowenjing/18/code/r55/upgrade_os_og_bokeh_deconf.py) 中，为 **`过锐`（`dim=2`）** 设计 11 维逐图独立协变量（融合 `v16 / p3_qy / p12_pe / ntg_convnext` 1:1 边缘振铃显微镜均值与全局/VLM 语义响应之差 `micro_vs_global_gap`、`vlm_overcall_gap`），并采用 **零截距秩-1 序数斜率约束** $\Delta z_{i,k} = k \cdot (x_i^\top \beta)$ 与散景协同门控 `BokehSynergy`，推动线上得分由 `54.30` 升至 `54.44`；
  2. 随后在 [`code/r55/upgrade_deconf_v4_tile.py`](file:///wanqing-develop/luowenjing/18/code/r55/upgrade_deconf_v4_tile.py) 与 [`code/r55/ntg_tile_peak_probe.py`](file:///wanqing-develop/luowenjing/18/code/r55/ntg_tile_peak_probe.py) 中执行残差统计审计，发现 **`ntg_pe` 1:1 平铺切片的图内极值-均值尖峰度（`max_t - mean_t`）** 与 `过度生成` 残差相关性高达 `+0.144`（`6.3σ`），且在 `FinalEngine.infer()` 中可**零额外参数、零额外显存**直接复用前向切片张量提取；
  3. 引入 **双向 Clean 整图锁死 + 非目标维隔离 + 强 $L_2 = 450$ 收缩** 的 24 维 `deconf_v4_tile` 校准器，推动线上刷新纪录至 **`54.68 / 65`**；
  4. **终极两阶段全维度边界攻坚（`deconf_v5_boundary → resident_v8_boundary + deconf_v6_boundary`，线上 `54.77 / 65`）**：在 `Clean` 满分稳锁后，人类研究者指令“分两阶段攻坚全维度 `P0/P1/P2` 边界（先 Decoder 再模型层）”。AI 严格按两阶段推进：先完成 `deconf_v5_boundary`（`+0.055`），再全新训练 2 个 100% Tag-Free Stage 2B 边界专精塔（`bndry_pe`, `bndry_dual`），并构建 **单 4-bit 底座双适配器共享 VLM（`DualAdapterQwen3VL4090`）** 合入高分语义 ROI 模型 `qwen_hr`，最终通过 **Pre-LRO 零稀释融合**（`deconf_v6_boundary`）将 8-Fold 零泄漏 OOF 推升至 **`52.665`（`ALL 51.958`，`Perm654<15 = 0.00%`）**，线上 `test_150` 再创新高 **`54.77 / 65`**（`正向缺陷 17.46/25`、`P0 17.31/20`、`Clean 20.00/20` 满分）！

### 实例 3：面向单卡 RTX 4090（`S_cost` 20 分）的四重无损显存压缩与延迟加速闭环
- **人类关键洞察**：审视专精成员列表与主观成本评分细则后指出：**① 多个专精模型共享同一预训练主干且仅微调顶层，底层显存可直接合并；② 单卡 24 GB 若峰值在 `21 GiB` 仍存在“资源余量不足”评审风险，要求在不损 1 格精度的前提下进一步把峰值显存压至 `19 GiB` 以下并压低单图延迟**。
- **AI 工程落地与受控消融**：在 [`code/r55/final_engine.py`](file:///wanqing-develop/luowenjing/18/code/r55/final_engine.py) 与 [`code/r55/dual_vlm_shared_4090.py`](file:///wanqing-develop/luowenjing/18/code/r55/dual_vlm_shared_4090.py) 中落地四重压缩并完成严格零差异验证：
  - 冻结层逐元素 `torch.equal` 显存共享（**无损省 `5.81 GB`**）+ 单 4-bit NF4 底座双适配器共享 VLM（**省 `3.40 GB`**）+ Host 词表卸载（**省 `1.16 GB`**）；
  - 受控对比纯 PyTorch `FP8 E4M3` vs 对称 `INT8 group-128` 权重量化，果断淘汰产生漂移的 `sig_v3`（`max_TV=0.156`）与已共享的 `dinov3l`，**仅精准量化 `v16` 独有未共享 1.88B `PE-Core-G14`**（再省 **`1.72 GiB`**，100% BF16 激活、零外部依赖），叠加 `ntg_convnext (tile_chunk=4)` / `cradio_v3` 比特精确激活分块与共享冻结前缀计算；
  - 最终 14 成员常驻降至 **`15.78 GB`**、`nvidia-smi` 推理峰值暴降至 **`18.49 GiB`（加载峰 `19.98 GiB < 24 GiB`，RTX 4090 推理余量扩至 `~5.50 GiB`）**，全量 `test_150` 端到端均耗由 `4.89s` 提速至 **`3.03s`（最大 `6.93s <= 15s`）** 且严格 **`0 / 900` 格差异**；同期受控完成 `resident_v8_boundary_novlm` 纯视觉轻量档实测（线上 **`54.52 / 65`**、`nvidia-smi` 峰值 **`12.75 GiB`**、中位 `2.39s`），验证了双 8B VLM 带来真实 `+0.25` 线上增益并确立双档帕累托前沿。

### 实例 4：AI 自我审计修复语义归因缺陷（对齐 `+5` 语义判断能力）
- **自查发现问题**：AI 对早期归因输出执行全量统计自检时发现三项隐患：① `midblock_hier8` 子块锐化放大了峰值均值比，导致均匀全图模糊/涂抹过画局部框；② 固定 `P90` 绝对阈值忽略 `P1/P2` 中轻度梯度和局部/全图相对对比，导致 `final_644` 实测支持率仅 `18.3%` 且文案模板重复；③ 黑边竖屏图偶发 `global_value = 0.0` 除零异常。
- **闭环修复**：
  1. 在 [`code/r55/subjective_engineering.py`](file:///wanqing-develop/luowenjing/18/code/r55/subjective_engineering.py) 中收紧未放大 **`4×4` 粗粒度空间集中度门控**，使 `final_644` 弥散退化准确标注 `"全图"` **301 次**，局部伪影输出 `8×8` 像素框 **1,045 次** 并绑定零幻觉像素视觉区域提示（`人像肤色区/高反差边缘/暗部区域`等）；
  2. 在 [`code/r55/measured_evidence.py`](file:///wanqing-develop/luowenjing/18/code/r55/measured_evidence.py) 中排除黑边平坦块彻底消除 `zero_global_value` Bug（`0` 次），引入 **分层洁净分位（`P0:P90 / P1:P82 / P2:P75`）+ 局部/全图相对对比（`±20%`）**，推动物理实测 `supports` 翻倍至 **`36.4%` (`test_150`) / `40.2%` (`final_644`)**、去模板唯一理由率达 **`94.5%` / `87.4%`**，并在 [`build_v8_delivery_sidecars_and_audits.py`](file:///wanqing-develop/luowenjing/18/code/r55/build_v8_delivery_sidecars_and_audits.py) 中新增真图局部框物理对比定量审计（`final_644` 命中率 **`61.5%`**，`花屏 70.0%`、`模糊 69.2%`），同时 `100%` 保留诚实的单帧因果不确定性说明。

## 三、 工程纪律与可信 AI 研发规范（Persistent Guardrails）

为防止 AI 智能体在长周期迭代中滑向“刷榜过拟合”或“不可交付的庞大堆叠”，本团队建立了三道硬性机制：
1. **持久化记忆规则（`AGENTS.md`）**：每次会话自动加载三条不可逾越红线——严禁读取任何历史测试集 JSON 做锚定覆写、严禁测试集调参或凑格数、严禁使用预存特征缓存或超预算模型池。
2. **单图流式等价与零训练读取审计**：推理引擎内置 `N=1 vs N=batch` 自动逐格比对（实测 **`0 / 900`**、**`0 / 3864`** 差异）及 `open()` 系统调用审计钩子（`R55_AUDIT_TRAIN_READS=1`，实测推理全程读取训练数据 **`0` 次**）。
3. **完全断网（Air-Gapped）预检闭环**：通过 [`code/r55/check_deploy_env.py`](file:///wanqing-develop/luowenjing/18/code/r55/check_deploy_env.py) 对 Python 依赖、4-bit NF4 算子、RTX 4090 `sm_89` SASS 兼容性、14 个微调权重与全部本地基座开展 **65 项自动化体检（`0 FAIL, 0 WARN`）**，确保评审方在无外网环境下开箱即用。
