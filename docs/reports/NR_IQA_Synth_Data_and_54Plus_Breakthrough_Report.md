## 二、深度代码审计：为什么当前合成数据（V17）收益有限甚至在部分通道负迁移？

通过对合成数据生成脚本（code/synth/build_guide_isp_aigc_quadruplets_and_vlm_qc.py、code/synth/launch_8gpu_fr_delta_referee.py）与训练脚本（code/finetune/train_v17_end2end_sim2real_specialist.py、code/finetune/launch_v17_end2end_s16_s17_8gpus.py）的逐行审计，我们定位到了导致合成数据收益受限的【六大底层工程与物理病灶】：


### 2.1 病灶一：合成前强制将原图下采样至 max(h, w) = 960，彻底摧毁了 1:1 显微镜流的物理尺度！

- 代码定位：code/synth/launch_8gpu_fr_delta_referee.py 第 142~144 行 & build_guide_isp_aigc_quadruplets_and_vlm_qc.py 第 898~900 行：
- 问题代码：if max(h, w) > 960: scale = 960.0 / max(h, w); im = cv2.resize(im, ..., interpolation=cv2.INTER_AREA)
- 物理破坏机制：真实数据集图像绝大多数为 1080p ~ 4K（1920×1080 至 3840×2160）高清图。我们的 4 个专家专门设计了【1:1 原生像素显微镜流（Native Microscope Crops，切取 3 张 448×448 原生像素切片）】来捕捉 1 像素级振铃、皮肤毛孔涂抹与微小 AIGC 笔画粘连。然而，合成脚本在施加任何退化之前，先把所有干净种子图暴力缩小到了长边 960（如 960×540）！
- 直接后果：① 从 960×540 合成图上切出的 448×448 切片，实际覆盖了全图 83% 的高度（变成了伪全局图），与真实 2K/4K 图上 448×448 局部显微镜切片的空间尺度（Field of View）相差 2.5~3 倍！② cv2.INTER_AREA 下采样在合成前就抹平了原图真实的传感器底噪与原生锐度，导致显微镜分支学到了“分辨率被缩小 = 有合成缺陷”的虚假域偏移（Domain Shift）。


### 2.2 病灶二：所谓的“FR-Delta 神经裁判”退化成了无监督特征 L2 距离判断（99% 放行率），完全未对齐人类等级走廊！

- 代码定位：code/synth/launch_8gpu_fr_delta_referee.py 第 204~214 行（实际生成 /dev/shm/v17_synth_quads 的脚本）：
- 问题代码：diff_p2 = torch.norm(feats[1:2] - f0, p=2); passed = (diff_p2 >= 0.015 and diff_p1 >= diff_p2 + 0.012 and diff_p0 >= diff_p1 + 0.018)
- 物理破坏机制：原本的设计蓝图要求使用训练好的教师分类头（如 InternViT-6B）计算预测退化等级期望值 S_c(I) ∈ [0, 3]，确保合成的 P2 落在真实人类 P2 置信区间 [0.4, 1.1]、合成 P1 落在 [1.45, 2.25]、合成 P0 落在 [2.4, 3.0]。但实际执行的脚本只算了无监督 SigLIP2 特征向量的 L2 欧氏距离！
- 直接后果：只要算子参数递增（模糊核变大、USM 系数变大），图像像素变化变大，SigLIP2 特征的 L2 距离 100% 必然单调递增！结果导致 295 个训练种子生成的候选四元组几乎 99% 全数放行（s16 中模糊 879 张、过锐 873 张、纹理损失 867 张）。大量合成 P0 的模糊/涂抹程度远超真实人类的 P0 阈值下界，模型在 Stage 1 见多了“极端夸张的合成 P0”，把 P0 触发门槛拉高，直接导致盲测集上真实【模糊_P0 漏检激增 22 张】、【纹理损失_P0 漏检激增 23 张】，S_p0 暴跌 0.40 分！


### 2.3 病灶三：四元组 (Clean, P2, P1, P0) 在训练时被拆散随机打乱（shuffle=True），完全丢失了同场景差分排序学习！

- 代码定位：code/finetune/train_v17_end2end_sim2real_specialist.py 第 296~329 行：
- 问题代码：tr_stage1 = list(tr_real) + tr_synth; ltr_s1 = DataLoader(dtr_s1, batch_size=8, shuffle=True)
- 物理破坏机制：我们费尽周折从同一张干净原图 I_Clean 合成有序四元组 (I_Clean, I_P2, I_P1, I_P0) 的唯一核心数学价值，是在同一个 Batch 内对同一场景计算【成对特征差分单调排序损失】 L_rank(S(I_P0) - S(I_P1), S(I_P1) - S(I_P2), S(I_P2) - S(I_Clean))，从而 100% 抵消背景语义内容偏差 b_scene(I)！
- 直接后果：训练脚本却把 3,770 张合成图拆成孤立单图，塞进 5,800 张图的池子里做随机 shuffle（batch_size=8）。在大小为 8 的随机 Batch 里，同一个种子的 P2 和 P1 出现在同一 Batch 的概率不足 0.1%！模型在 Stage 1 根本没有做同场景对比学习，反而因为同一个干净背景被重复塞入 12~14 次，导致骨干网络对这 295 张种子图的背景产生记忆过拟合。


### 2.4 病灶四：局部缺陷合成（仅占全图 2.5%~11% 面积）与训练时“盲取最高梯度切片”冲突，导致干净切片被当成缺陷训练！

- 代码定位：build_guide_isp_aigc_quadruplets_and_vlm_qc.py 第 536~549 行 vs train_v17_end2end_sim2real_specialist.py 第 152~181 行：
- 物理破坏机制：① 在合成过度生成（OverGen）时，P2 仅在背景非敏感区生成一个占全图面积 2.5%~4.8% 的微小椭圆掩码，P1 仅占 6%~11% 面积；② 然而训练加载器 _extract_native_microscope_crops 并不知道合成掩码在哪里，而是按 3×3 网格盲目计算绿色通道梯度能量（Sobel + Laplacian），强行挑出全图梯度最高的前 2 个切片（p_peak1, p_peak2）送入显微镜分支！
- 直接后果：对于合成的【纹理损失】或【局部平滑】（退化区域的梯度恰恰被抹低了！）以及处于低梯度背景区的【过度生成_P2】，梯度最高的 Top-2 切片 100% 避开了合成退化区，切出来的全是未受损的干净锐利区域，但标签却强行监督为 P2 / P1！这相当于直接往 1:1 显微镜流里注入了高比例的标签噪声（Clean Patch Labeled as Defect）。


### 2.5 病灶五：过度生成（OverGen）的 P1/P0 混入了手工正弦波扭曲（cv2.remap）与高斯噪声，偏离真实 AIGC 分布

- 代码定位：build_guide_isp_aigc_quadruplets_and_vlm_qc.py 第 523~558 行：
- 问题代码：dx_p0 = 16.0 * np.sin(yy / 7.0) + 8.0 * np.cos(xx / 5.0); burned_p0 = warped_p0 + 2.6 * hf_p0 * (1 + N(0, 0.35))
- 物理破坏机制：真实数据集中的过度生成（OverGen）源于扩散模型超分/重绘产生的“塑料蜡像感皮肤、伪造的高频毛发/文字笔画畸变、局部油画感纹理”。但合成脚本在生成 P1/P0 时，在随机椭圆区域内叠加了固定频率的正弦波哈哈镜扭曲（sin/cos 周期网格形变）和像素级高斯白噪声。这种人工规则算子痕迹极易被深度卷积/ViT 识别为合成捷径，无法泛化到真实的扩散生成伪影。


### 2.6 病灶六：专门为【虚化突兀】合成的“自然光学景深困难负样本”在构建训练清单时被 100% 漏加载！

- 代码定位：code/finetune/launch_v17_end2end_s16_s17_8gpus.py 第 44~47 行：
- 问题代码：if c_name in FULL: grades_to_use = ['P2', 'P1', 'P0'] else: grades_to_use = ['P0']
- 物理破坏机制：在合成虚化突兀（dim_c=5）时，合成脚本专门用连续深度图生成了【自然渐进光学景深图 I_natural_bokeh】，并保存为 {stem}_d5_P2.png，本意是作为 Hard Negative（标签设为：虚化突兀=0，模糊=0）喂给模型，教会模型区分“真单反大光圈自然浅景深”与“假抠图断层虚化”以及防止把自然背景虚化误判为“模糊_P2”。
- 直接后果：由于 launch_v17_end2end_s16_s17_8gpus.py 写了 else: grades_to_use = ['P0']，所有生成的 _d5_P2.png 困难负样本被 100% 过滤丢弃，一张都没有进入训练集！这也是为什么【模糊_P2】假阳性依然高达 236 张（大量自然浅景深被误判为模糊 P2）的直接原因。


## 三、机制复盘：为什么当前的“一票否决（One-Vote Veto）”只带来了 +0.53 分提升？

当前在 code/finetune/infer_4spec_6b_test150.py 中实现的后处理一票否决，虽然将双盲测均值从 4 专家的 52.822 推到了 53.351（+0.529 分），但距离 54+ 仍有明显距离。通过表 1.2 的对比，可以清晰看到后处理硬否决的三大局限性：

- 1. 硬取大（np.maximum）升级否决会同时放大假阳性（FP 并集效应）：在【过度生成_P2】上，6B 单模 F1 为 34.66%（TP=61, FP=135），SpecA 单模 F1 为 31.62%。当执行 p2 = np.maximum(p2, 0.94 * np.maximum(a_p2_og, b6_p2_og)) 时，TP 仅从 61 增加到 64（+3 个），但 FP 却从 135 暴增到 174（+39 个）！导致融合后的【过度生成_P2】F1（32.49%）反而比 6B 单模（34.66%）倒退了 -2.17%！
- 2. 6B 基座在优势通道上的话语权过低（被 4 专家平均稀释）：从表 1.2 可见，在【过锐_P1】上，6B 基座单模 F1 高达 45.41%（TP=94），远高于 V17 4专家的 38.25%（TP=70）；在【过锐_P0】上，6B 基座单模 F1 高达 73.65%，同样高于 4 专家的 69.93%。但在当前融合公式中，过锐通道仅给 6B 分配了 w6 = 0.18 的低权重，且没有赋予 6B 对过锐 P1/P0 的主导权，导致融合后过锐 P1 被拉低了 -3.50%！
- 3. 推理期后处理无法替代训练期表征学习：4 个专家使用的是 300M~400M 级中轻量视觉主干（PE-Core / DINOv3-L / SigLIP2 / ConvNeXt），而基座是 6B 参数量的 InternViT-6B。仅靠推理阶段对输出概率做线性加权或阈值截断，无法让 4 个专家的内部特征空间真正对齐 6B 大模型的细粒度排序边界。


## 四、破局方案：零作弊前提下，将【6B + 4 专家】双盲测均值推上 54.0+ 的四大核心升级

围绕【InternViT-6B + 4 个领域专家】这一最终可上线架构，不在测试集做任何微调、不引入任何额外推理模型，我们从【合成数据物理保真重构】、【成对四元组差分训练】、【训练期 6B-to-4Spec 知识蒸馏】与【通道级贝叶斯协同门控】四个维度制定 V18 冲刺 54+ 方案：


### 4.1 方案一：合成数据流水线四大外科手术修复（解决负迁移与尺度失真）

| 修复项 | 针对病灶 | 具体工程实现方案 | 预期解决的指标瓶颈 |

### 4.2 方案二：训练范式升级——同种子四元组差分排序学习（Paired Quadruplet Differential Ranking）

- 1. 废除“3,770 张合成图无脑混洗淹没真图”：不再把合成图拆散当作普通样本淹没训练集（将合成样本在每个 Epoch 的采样占比严格控制在 25%~30%）。
- 2. 引入成对差分采样（Paired Seed-Quadruplet Contrast）：每次采样一个合成种子时，同步提取该种子在同一焦点坐标 (cy, cx) 下的 (I_Clean, I_P2, I_P1, I_P0) 特征表示，直接对分类头 logit 施加同场景成对单调间隔损失：
-    L_quad = max(0, m_1 - (z_c(I_P2) - z_c(I_Clean))) + max(0, m_2 - (z_c(I_P1) - z_c(I_P2))) + max(0, m_3 - (z_c(I_P0) - z_c(I_P1)))
- 3. 核心优势：只让合成四元组负责训练【同场景下退化程度微增时的特征单调导数（∂z_c / ∂severity > 0）】，而不让合成图去篡改模型的全局类别先验偏置（bias）！这样既能学到极细粒度的 P2/P1 等级排序，又绝不会拉偏真实图像的 P0 触发阈值。


### 4.3 方案三：零泄漏的【6B 基座 -> 4 专家】训练期跨架构知识蒸馏（6B Teacher Distillation）

- 核心洞察：目前 6B 基座与 4 个专家是完全各自独立训练对硬标签（0/1/2/3）做拟合的。但在训练集中，许多处于 P1/P2 边界的真实样本具有连续的退化程度，硬标签无法传递这种边界信息；且 6B 在【过锐_P1/P0】、【纹理损失_P0】上远强于 4 专家。
- 零泄漏实施方案：在 s16 训练时，只使用 s16 自身训练出的 6B 模型（v12_phaseB_fixed_s16 + iv6b_s16）；在 s17 训练时，只使用 s17 自身训练出的 6B 模型（100% 零跨折泄漏）。
- 蒸馏损失设计：在训练 4 个专家（SpecA/B/C/D）时，对真实训练图像加入温度 T=1.5 的概率分布蒸馏项：
-    L_total = (1 - λ_kd) * L_real_hard(y_true) + λ_kd * L_BCE(p_spec, p_6B_teacher) + μ * L_quad_ranking
- 预期收益：让 4 个轻量专家在训练阶段就吸收 6B 大模型的全局语义抗噪能力与过锐/过度生成边界，单专家合流即可直接跃升 +0.35~0.45 分！


### 4.4 方案四：用“验证集驱动的通道级优势路由 + 双证协同门控”升级当前粗糙的一票否决

- 1. 修复 6B 优势通道权重倒挂：在验证集（va）上按通道 F1 分配 6B 与专家的融合权重——对于 6B 显著占优的【过锐_P1/P0】、【纹理损失_P0】，将 6B 权重从 0.18 提升至 0.50~0.60，并由 SpecB 的 1:1 显微镜高频振铃特征提供确认门控。
- 2. 将【过度生成_P2】的单方硬取大（maximum）改为“双证协同门控（Dual-Evidence Gate）”：不再只要 SpecA 或 6B 有一方过阈值就强行判 P2（导致 FP 暴增 39 个），而是要求：要么最高一方极高置信度（> T2 + 0.08），要么 SpecA 与 6B 同时给出中等以上响应（双方几何均值 sqrt(p_SpecA * p_6B) > T2），在保住召回的同时砍掉单模偶发假阳性。
